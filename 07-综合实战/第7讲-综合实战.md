# 第 7 讲：综合实战 —— 完整链路跑通一个真实项目

> 🎬 录制钩子（前 10 秒）：「前面 7 讲都是零件。今天我用一个真实项目，把 34 个技能串成一条流水线跑完——你看完全程，就知道这套系统为什么值钱。」

## 一、综合链路总图

```
① 入口编排  /dbs 「我有个模糊的困惑」
       │  自动判断：单技能 or 1主+2辅
       ▼
② 好问题    dbs-good-question  把困惑钉成可验证的问题说明书
       │
       ▼
③ 商业诊断  dbs-diagnosis      问诊：消解问题 / 体检：拆商业模式
       │  （需要时）dbs-benchmark 找对标，五重过滤
       ▼
④ 执行疏通  dbs-action         知道但不做？先解决心理问题
       │      dbs-goal         把愿望变成可验收交付物
       ▼
⑤ 内容生产  dbs-content → dbs-hook / dbs-xhs-title
       │      → dbs-script-flow / dbs-ai-check / dbs-content-risk-check
       │      → dbs-wechat-html
       ▼
⑥ 数据回收  dbs-video-extract  看数据、提文案、做复盘
       │
       ▼
⑦ 资产沉淀  dbs-save → dbs-report → dbs-skill-maker
```

## 二、实战剧本（录视频时按这个顺序跑）

### 场景：一个想做知识付费但半年没起色的人

**Step 1｜入口编排**
输入：`/dbs 我做了半年职场知识付费，小红书发了 80 篇，只有 30 个粉丝，不知道问题在哪`
观察点：它不直接回答，而是先判断该用哪个技能，输出一段可发送的提示词。

**Step 2｜好问题改写**
输入上面那段话 → dbs-good-question 追问：80 篇里哪几篇数据最好？私信咨询有多少人？转化了几单？
产出：问题从「为什么没起色」变成「笔记平均收藏率 X%，私信 Y 人，0 成交——瓶颈在内容还是产品？」

**Step 3｜商业诊断**
dbs-diagnosis 问诊 → 大概率消解出：**问题不是流量，是产品**（公理 4：流量≠收入；原则 4：先有产品后有内容）
→ dbs-benchmark 找 3 个同赛道真正赚钱的对标，五重过滤 + 模仿颗粒度检查表

**Step 4｜执行疏通**
dbs-action：「你说要改产品，说了两个月没动。卡在哪？」
诊断：拖延维护的是「我只是还没开始」的人设

**Step 5｜内容生产**
dbs-content：选题（职场干货）→ 形式匹配（图文大字报，不是口播）
→ dbs-xhs-title：75 公式选 5 个，覆盖 3 类触发器，每个标注编号
→ dbs-script-flow 检查逐字稿 → dbs-ai-check 去 AI 味 → dbs-content-risk-check 发布前安检
→ 公众号版本用 dbs-wechat-html 排版

**Step 6｜数据回收**
dbs-video-extract：拉取自己/对标账号的数据 + 提取爆款文案，做「为什么这条火了」的对比

**Step 7｜资产沉淀**
dbs-save 存档本轮结论 → dbs-report 生成一份《职场知识付费诊断报告》
→ 用 dbs-skill-maker 把「怎么诊断小红书零转化」做成你自己的技能

## 三、这节课真正要讲的三件事

### 1. 系统的价值在「编排」，不在单个技能

任何一个技能，你都能用一句提示词自己写个七八成。但这套系统的价值在于：**它知道什么时候该用哪个，以及怎么组合**。这就是「入口 + 交接契约 + 组合契约」的设计目的。

### 2. 每个技能都是「公理 + 流程 + 禁止事项」

看懂了结构，你就能：
- 快速判断一个技能适不适合你的场景（看公理）
- 自己改造它（改公理 → 流程自然变）
- 自己写第 35 个（用 skill-maker）

### 3. 最该抄走的三件事

| 可抄物 | 为什么值钱 |
|---|---|
| 公理化的技能写法 | 让 AI 输出有立场，而不是骑墙的「看情况」 |
| 提示词与案例库分离 | 提示词管流程，案例库管直觉，各自可迭代 |
| 存档 + 交接契约 | 把一次性对话变成长期资产 |
