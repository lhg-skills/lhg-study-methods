# 第 6 讲：元技能 —— 存档流 + 自己做 Skill + 跨 Agent 迁移

> 🎬 录制钩子（前 10 秒）：「大多数 AI 对话，关掉窗口就归零。这套系统能让诊断跨会话续接、把重复问题变成新技能——今天讲它最被低估的部分。」

## 一、存档流：save / restore / report

### 为什么需要存档

AI 对话是一次性的，但**商业诊断是长期的**：一个决策要跟三个月，一次诊断要分五轮。存档把「对话」变成「资产」。

### 三个技能的分工

| 技能 | 作用 |
|---|---|
| dbs-save | 把当前诊断的关键状态存到本地（标题、结论、待办、next_skill） |
| dbs-restore | 恢复最近一次存档，接着上次继续 |
| dbs-report | 把多次存档合并成一份可交付的 Markdown 报告 |

### 设计细节（值得学）

1. **项目隔离（slug）**：不同项目分开存档，互不污染
2. **存档根目录可配置**：默认本地，可改路径（便于放进 Obsidian / 网盘）
3. **Step 1 先判断「现在能不能存」**：信息不足以支撑续接时不硬存
4. **next_skill 字段**：存档里记录下一步该用哪个技能——这就是「交接契约」的落地方式，恢复时不用你重新判断

## 二、dbs-skill-maker：把反复出现的问题做成技能

**核心逻辑**：任何问过 3 次以上的问题，都值得变成一个技能。

流程：需求分析 → 分级验证 → 产出可安装的单个 Skill。

**这是 dbskill 能自生长的原因**，也是它和普通提示词包的根本差异：普通包是静态的，这个系统有「把经验固化」的机制。

**给你的启示**（做视频时可以重点讲）：你自己日常被问最多的问题是什么？那就是你该做的第一个技能。

## 三、dbs-learning：把课题拆成连续课程

**这套技能本身就在用这个技能的设计**：

- 触发信号：「想系统学习一个主题」「想连续写课」「根据上一篇反馈生成下一篇」
- 核心机制：**根据用户反馈调整后续深度、角度和节奏**——不是一次性生成全部课程，而是「一篇 → 反馈 → 下一篇」
- 文件规则：用户指定目录 > 项目目录/学习课题/{课题名}/

**这就是本仓库采用的教学法**（先出第 0 讲，你看完给反馈，我再调节节奏往下写）。

## 四、dbs-knowledge / dbs-content-system：知识资产化

| 技能 | 解决什么 |
|---|---|
| dbs-knowledge | 把本地文件夹建成 Agent 可稳定查找的知识库（导航、版本判断、健康检查、SOT 分层） |
| dbs-content-system | 把散落的文稿/推文/案例整理成可重组复用的内容工程 |

**内容单元抽取与可用态标准**（知识包文件名）——把内容拆成「单元」，标注可用状态，这才是内容工业化，而不是「写很多篇」。

## 五、跨 Agent 与迁移

| 技能 | 作用 |
|---|---|
| dbs-install-skill | 把技能装到 Claude Code / Codex / Hermes / Cursor / Qwen Code / Cline / WorkBuddy / Grok / Kiro |
| dbs-agent-migration | 审计项目规则文件、识别真源、统一命名、生成桥接，迁移成多端一致的 Agent 工作台 |
| dbs-update | 官方更新：24 小时一次版本检查，保留你的存档和其他技能 |

**学习点**：它把「Agent 配置文件碎片化」当成一个真实问题来解决（AGENTS.md / CLAUDE.md / .cursorrules 多端重复）——这是所有多端使用 AI 的人都会遇到的痛点。

## 六、dbs-chatroom：多专家圆桌

根据话题推荐专家、模拟多角色对话并总结分歧；`dbs-chatroom-austrian` 是哈耶克 + 米塞斯的奥派专场。

**用途**：不是娱乐，是**用不同理论框架互相碰撞来暴露你的思维缺口**。
