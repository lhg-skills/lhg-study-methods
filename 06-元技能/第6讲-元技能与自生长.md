# 第 6 讲：元技能 —— 存档流 + 自己做 Skill + 跨 Agent 迁移

> 🎬 录制钩子（前 10 秒）：「你有没有发现，跟 AI 聊完天，关掉窗口它就全忘了？下次还得从头讲一遍。今天这讲告诉你，怎么让 AI 记住你——还能自己长出新本事。」

## 🗣️ 人话版（说给朋友听，不超过 5 句）

1. 你跟 AI 聊天，关掉窗口它就失忆，下次还得从头讲一遍。
2. 这套系统有个"存档"功能，能把聊到一半的事存下来，下次打开接着聊。
3. 更厉害的是：同一个问题你问过 3 次，它就把经验做成一个新技能，以后不用再教。
4. 所以它越用越聪明——不是靠你投喂，而是靠它自己"长"。
5. 今天就把这套"记住 + 生长"的本事，掰开讲给你听。

## 场景切入：你肯定遇到过……

去医院看慢性病，医生每次都先翻你的病历本："上次开的药吃完了吗？效果怎么样？"——因为病历本记着上次聊到哪了。

可你跟 AI 聊天呢？每次打开都是第一次见面。上次让它帮你分析的那个项目，这次它全忘了，你得从"我是干啥的"开始重讲一遍。

还有一种烦：家里老人学用智能手机，"怎么发语音"这个问题问了你 5 次。第 6 次你学聪明了，直接写张纸条贴冰箱上——以后他再问，你指一下冰箱就行。

今天这讲，就是 AI 版的"病历本"和"冰箱纸条"。

## 掰开讲

### 一、存档：给 AI 配个"病历本"

**生活类比**：玩单机游戏打 Boss，打到一半先存个档。明天打开游戏读档，接着打，不用从第一关重来。

AI 对话本来是一次性的，关了就没。但**商业诊断是长期的**：一个决策要跟三个月，一次诊断要分五轮聊。没有存档，每轮都是从零开始。

所以这套系统做了三个配套动作：

- **存**：聊到一半，按下存档键——现在聊到哪了、结论是啥、下一步干啥，全记下来。哪怕你关掉窗口，东西还在。
- **读**：下次打开，读档，接着上次的话头继续，不用重讲背景。
- **出报告**：攒了好几次存档，一键拼成一份正式的 Markdown 报告，能直接交差。

几个设计细节，特别值得学：

1. **不同项目分开存**：A 项目的存档和 B 项目的不掺和。就像不同病人的病历本分开放，不会串。
2. **存档里写好"下一步干啥"**：存的时候就记下下次该用哪个技能，恢复时不用你重新判断——像护士交接班，本子上写好"下一班先给 3 床量血压"。
3. **信息不够不硬存**：还没聊出有用的东西，就不存。病历不能瞎写，没确诊不乱记。
4. **存档放哪儿你说了算**：默认存本地，路径可以改——想放进 Obsidian、放进网盘都行。就像病历本放家里抽屉还是随身带，你定。

**这个东西，行话叫"存档流"，三个技能叫 dbs-save、dbs-restore、dbs-report。**记住一句话就行：**存档把"对话"变成了"资产"。**

### 二、重复 3 次的问题，变成一个新技能

**生活类比**：回到冰箱上的纸条。你妈被问了 5 次"红烧肉怎么做"，干脆写成菜谱贴墙上。以后谁问，看墙就行，不用再动嘴。

核心逻辑就一句话：**任何问过 3 次以上的问题，都值得变成一个技能。**

为啥是 3 次？问 1 次可能是偶然，问 3 次说明这不是一次性问题，是个"反复出现的活儿"。一次性问题口头答完就完，反复出现的活儿值得"腌成咸菜"存起来。

做成技能分三步：先搞清楚到底要解决啥（需求分析）→ 试几遍看靠不靠谱（分级验证）→ 打包成别人也能装的单个技能。

**这是 dbskill 能自己生长的原因，也是它和普通提示词包的根本差异**：普通包是静态的，写死不变；这个系统有个"把经验固化"的机制，越用技能越多。

**这个东西，行话叫 dbs-skill-maker。**

给你留个启示（做视频可以重点讲）：你自己日常被问最多的问题是什么？那就是你该做的第一个技能。

### 三、学东西，一篇一篇来，别一次倒完

**生活类比**：好老师上课，从来不是开学第一天就把一学期的内容全讲完。而是讲一节，看你们懂没懂、感兴趣的是哪块，再决定下节讲深讲浅。

你想系统学一个大主题，它不一次全倒给你，而是：一篇 → 看你的反馈 → 再写下一篇。每篇都根据你的反馈调深度、调角度、调节奏。

触发信号很简单：你说"想系统学个东西""想连续写课""根据上一篇的反馈生成下一篇"，它就进入这种模式。课程文件放哪儿也有规矩：你指定的目录优先，没有就按"项目目录 / 学习课题 / 课题名"放。

**好玩的是：你现在看的这套 8 讲课程，就是这么写出来的**——先出第 0 讲，你看完给反馈，我再调节奏往下写。现身说法。

**这个东西，行话叫 dbs-learning。**

### 四、把乱七八糟的东西，变成"资产"

**生活类比**：整理房间。东西堆在地上叫"杂物"，分门别类放进柜子、贴上标签，才叫"资产"。知识和内容也一样。

两个动作：

- **管知识**：把你电脑里的文件夹，变成 AI 能稳定找到东西的知识库——有导航、能判断版本对不对、定期体检（健康检查）。东西再多也不乱。
- **管内容**：把散落在各处的文稿、推文、案例，拆成一个个"内容单元"，标注每个单元能不能用、好不好用。以后写新文章，直接组装零件就行。这叫**内容工业化**，而不是"写很多篇"。

记住那个关键词：**内容单元抽取与可用态标准**——拆成单元、标好状态，才是资产。

**这两个东西，行话叫 dbs-knowledge 和 dbs-content-system。**

### 五、9 个 AI 工具，一套规矩通用

**生活类比**：搬家。你同时用 9 个 AI 工具，每个都要重新教一遍规矩，烦不烦？就像搬了 9 次家，每次都要重新跟物业报备。

三个配套动作：

- **一键安装**：技能一次打包，9 个平台都能装——Claude Code、Codex、Hermes、Cursor、Qwen Code、Cline、WorkBuddy、Grok、Kiro。不用每个工具重复配置。
- **搬家统一**：把散落在各处的规矩文件（AGENTS.md、CLAUDE.md、.cursorrules）收拢：审计一遍、认准哪个是真源、统一命名、生成桥接——像搬家时把 3 个房子的东西登记造册、统一编号，从此多端一致。
- **官方更新**：24 小时检查一次有没有新版本，有就升。但你的存档、你装的技能，原样保留——像手机系统更新，不删你的照片。

它解决的是一个真痛点：**Agent 配置文件碎片化**——所有多端用 AI 的人，都会遇到"规矩散得到处都是"。

**这三个东西，行话叫 dbs-install-skill、dbs-agent-migration、dbs-update。**

### 六、请几个专家来"会诊"

**生活类比**：疑难杂症，一个医生拿不准，就叫几个专家来会诊，互相挑刺，最后综合出个靠谱方案。

根据话题请专家、模拟多角色对话、最后总结他们的分歧。比如有个奥派专场，请的是哈耶克 + 米塞斯，专门用奥地利学派的框架看问题。

注意，**这不是娱乐**，是拿不同理论框架互相碰撞，**逼出你的思维缺口**——你自己想不到的，几个专家吵一架就露出来了。

**这个东西，行话叫 dbs-chatroom**（那个奥派专场叫 dbs-chatroom-austrian）。

## ✅ 讲给别人听（自测）

讲不顺 = 没真懂，回去重看上面那节。

1. 一句话：存档流解决的是什么问题？（参考：让 AI 的对话能"存档读档"，长期任务不用每次从头讲。）
2. 一句话：为啥"问过 3 次的问题"值得做成技能？（参考：出现 3 次说明不是一次性问题，是反复出现的活儿，值得固化。）
3. 一句话：dbs-learning 和"一次生成全部课程"有啥不一样？（参考：它是"一篇 → 反馈 → 下一篇"，根据反馈调深度和节奏。）

## ✍️ 本讲作业

1. 找一个人，把"存档流"讲给他听——记下他哪个地方没听懂，那个地方就是你自己没真懂的地方，回来重看。
2. 列出你最近 3 个月被问过 3 次以上的问题，挑一个，用"纸条贴冰箱"的思路写出它的技能大纲（要解决啥 → 怎么验证靠谱 → 打包成啥样）。
3. 动手跑一次 dbs-save，再跑一次 dbs-restore，亲手体验"关掉窗口、读档接着聊"。

## 🎬 录制脚本建议（18-22 分钟）

1. **0:00-0:30** 钩子：关掉窗口就归零，你受够了没
2. **0:30-2:00** 场景切入：病历本 + 冰箱纸条（观众秒懂）
3. **2:00-8:00** 掰开讲·存档流：游戏存档类比 → 存/读/出报告 → 分开存、next_skill 交接班、先判断能不能存、存档路径可改 → 亮术语 dbs-save / restore / report
4. **8:00-13:00** 掰开讲·skill-maker：3 次规则 + 菜谱类比 + "自生长 vs 静态包"根本差异 + 启示（被问最多的问题）
5. **13:00-16:00** 掰开讲·learning：老师上课类比 + "本课程就是这么生成的"现身说法
6. **16:00-20:00** 知识资产化（整理房间类比）+ 跨 Agent 迁移（搬家类比，9 平台名单）+ chatroom 会诊
7. **结尾** 自测题 + 作业 + 预告第 7 讲综合实战
