# 第 0 讲：全貌地图 —— 34 个技能的商业 AI 工具箱

> 🎬 录制钩子（前 10 秒）：「你是不是也这样：AI 工具装了一堆，账号该不赚钱还是不赚钱？问题不在工具，在你缺一套'先看病、再开药'的诊断系统。今天起，我用 8 讲，带你拆开一套有 34 个技能的商业 AI 工具箱——dbskill。」

## 🗣️ 人话版（整讲 5 句话）

1. 有个叫 dbskill 的开源工具箱，里面装了 34 个 AI 技能，专门帮人解决做生意时遇到的真问题。
2. 它最牛的一句话是：好 AI 不直接回答你，它先判断"你的问题本身是不是问错了"——8000 多人花钱问商业问题，99.1% 最后发现问错了。
3. 你不用记 34 个技能都是干嘛的：只管把烦心事说出来，有个"大堂经理"帮你挑人、组搭配。
4. 技能分六大类：看病诊断的、治拖延的、做内容的、学习的、扒视频数据的，还有管家型的。
5. 技能只管"怎么想"，真正的弹药（4200 多条知识、26 套案例）存在另一个"弹药库"里，两边分开，各自升级。

## 场景切入：你肯定遇到过

你想在小红书上卖点东西，但坐在手机前半小时，一个字都写不出来——不是你不努力，是你根本不知道第一步该干嘛。

或者换个场景：你去医院，不会一进门就跟医生说"我要吃阿莫西林"。你说的是"我嗓子疼了三天"，医生先问、再查、最后才开药。**先诊断，再开方**——这就是 dbskill 整套系统的思路。它不卖你"工具"，它给你配了一个"商业医院"：34 个技能就是 34 个科室，你只管说哪儿不舒服。

## 掰开讲

### 1. 这个"商业医院"里有什么

先看家底，全是实数：

- **34 个正式技能**：每个技能就是一份写给 AI 的"上岗说明书"，行话叫 SKILL.md——里面写着这个技能信奉什么公理、按什么流程干活、哪些事绝对不许干。
- **4200+ 条知识原子**："原子"就是被拆到最小的一条条知识卡片，按季度存在 JSONL 文件里（比如 `atoms_2024Q4.jsonl`），是系统的弹药。
- **26 个技能配套知识包**：每个技能配一套"方法论 + 案例库"，比如 `diagnosis_公理与诊断框架.md`。
- 这 16,152 条公开推文蒸馏出来的东西，覆盖五大方向：商业诊断、执行力、内容创作、学习系统、知识管理。

### 2. 核心哲学：不回答问题，消解问题

看病那个场景再往下想一层：病人说"我要退烧药"，医生一查发现是肺炎——这时候给退烧药就是害人，**问题本身问错了**。

dbskill 的立身之本就是一组数字：8000+ 人付费来问商业问题，最后只有 **0.9%** 被真正"解答"，**99.1%** 被"消解"了——因为那些问题本身就是错的。你问"我怎么做小红书"，它先帮你发现：你真正卡住的是"不知道卖什么"——问题一换，答案才有意义。

这个东西，行话叫"**消解问题**"。记住这句话：**好的 AI 不回答问题，它消解问题。**（知识包原话，整套 dbskill 的总纲）

### 3. 系统怎么运作：大堂经理的三件事

你不需要挑技能。整个系统只有一个入口，叫 `/dbs`——大白话就是**大堂经理**，行话叫"编排中心"。你随便说话，它走 5 步：

```
用户输入（随便说，不用挑技能）
        │
        ▼
   ┌─────────┐
   │  /dbs   │  ← 唯一入口 / 大堂经理
   └─────────┘
     │  1. 恢复当前唯一任务（接着上回聊，不让你重复描述）
     │  2. 发现技能：从 Marketplace 清单取候选（从 34 个科室里初筛）
     │  3. 筛选：5 项判断（任务结果/输入匹配/阶段匹配/边界匹配/可执行性）
     │  4. 判断：单技能够吗？不够 → 1 主 + 最多 2 辅（一个主治医生，最多配两个会诊的）
     │  5. 输出一段「可直接发送的提示词」（给你一张"就诊单"，拿去直接用）
     ▼
  下游技能执行（diagnosis / content / action ...）
```

它和普通提示词集合的本质区别，是三个关键设计（"三契约"）：

1. **入口不干活**：`/dbs` 只做分诊，本轮绝不提前给出诊断结论——"挂号处不看病"。它把「想清楚做什么」和「动手做」隔离开。
2. **组合有契约**：主技能管最终交付和停止条件；辅助技能只有三种角色——前置筛选、证据补充、验收约束。"主治医生说了算，会诊的不许各开各的药方"——绝不拼三份报告给你。
3. **跨技能交接契约**：叶子技能干完活就结束，不预设下一站；所有路由决策集中在入口。"看完一个科室就下班，不替你约下一个；信息跟着你的病历走，你不需要重复任何背景。"

### 4. 四种用法：去医院的四种挂号方式

| 方式 | 例子 | 大白话 |
|---|---|---|
| 直接调技能 | `/dbs-diagnosis 我想做小红书但不知道卖什么` | 已经明确要什么 → 直接挂专家号 |
| 交给入口编排 | `/dbs 我做了3个月抖音没起量，卡住了` | 不知道该用哪个 → 去分诊台 |
| 编号模式 | `/dbs 782` | 报暗号取"隐藏款"预制提示词（从公开仓库拉取，SHA-256 校验验明正品） |
| 目录查询 | `/dbs 给我所有隐藏款` | 把隐藏菜单全部打印出来看 |

### 5. 34 技能全景图（六大板块）

### 6. 弹药库：手艺和食材分开

```
知识库/
├── 原子库/atoms_2024Q4.jsonl ...     # 4200+ 知识原子，按季度
├── Skill知识包/                      # 26 个：如 diagnosis_公理与诊断框架.md
│   ├── 每技能配套方法论
│   └── 每技能配套案例库
└── 高频概念词典.md
```

打个比方：技能是"厨师的手艺"（**怎么思考**），知识包是"冰箱里的食材"（**用什么思考**）。这个系统最值得抄的一点，就是**提示词与知识包分离**——手艺和食材分开升级，互不耽误。
