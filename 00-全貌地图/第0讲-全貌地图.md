## 一、dbskill 是什么

dbskill 是 dontbesilent 开源的商业工具箱（GitHub: dontbesilent2025/dbskill），由 16,152 条公开推文蒸馏而成：

- **34 个正式技能**（每个是一个独立的 SKILL.md 提示词系统）
- **4200+ 结构化知识原子**（按季度存储的 JSONL 弹药库）
- **26 个技能配套知识包**（方法论 + 案例库）
- 覆盖：商业诊断、执行力、内容创作、学习系统、知识管理

**它的核心哲学只有一句话：好的 AI 不回答问题，它消解问题。** 8000+ 人付费问商业问题，只有 0.9% 被解答，99.1% 被消解——因为问题本身是错的。

## 二、系统如何运作（架构）

```
用户输入（随便说，不用挑技能）
        │
        ▼
   ┌─────────┐
   │  /dbs   │  ← 唯一入口 / 编排中心
   └─────────┘
     │  1. 恢复当前唯一任务（不让你重复描述）
     │  2. 发现技能：从 Marketplace 清单取候选
     │  3. 筛选：5 项判断（任务结果/输入匹配/阶段匹配/边界匹配/可执行性）
     │  4. 判断：单技能够吗？不够 → 1 主 + 最多 2 辅
     │  5. 输出一段「可直接发送的提示词」
     ▼
  下游技能执行（diagnosis / content / action ...）
```

**三个关键设计**（这是它和普通提示词集合的本质区别）：

1. **入口不干活**：`/dbs` 只做编排，本轮绝不提前给出诊断结论。隔离了「思考做什么」和「做」。
2. **组合有契约**：主技能管最终交付和停止条件；辅助技能只有三种角色——前置筛选、证据补充、验收约束。绝不拼三份报告给你。
3. **跨技能交接契约**：叶子技能干完活就结束，不预设下一站；所有路由决策集中在入口。信息跟着任务走，用户不需要重复任何背景。

## 三、四种调用方式

| 方式 | 例子 | 用途 |
|---|---|---|
| 直接调技能 | `/dbs-diagnosis 我想做小红书但不知道卖什么` | 已经明确要什么 |
| 交给入口编排 | `/dbs 我做了3个月抖音没起量，卡住了` | 不知道该用哪个 |
| 编号模式 | `/dbs 782` | 调用官方"隐藏款"预制提示词（从公开仓库拉取，SHA-256 校验） |
| 目录查询 | `/dbs 给我所有隐藏款` | 列出全部编号技能 |

## 五、知识库（弹药库）结构

```
知识库/
├── 原子库/atoms_2024Q4.jsonl ...     # 4200+ 知识原子，按季度
├── Skill知识包/                      # 26 个：如 diagnosis_公理与诊断框架.md
│   ├── 每技能配套方法论
│   └── 每技能配套案例库
└── 高频概念词典.md
```

技能负责「怎么思考」，知识包负责「用什么思考」。**提示词 + 案例库分离**，是这个系统最值得抄的架构。
